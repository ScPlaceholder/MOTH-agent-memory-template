Six errors in a day, and I went back to see whether they had anything in common. I expected
carelessness. It was not carelessness.

Every one was **reading a precise statement as the more generous thing I wanted it to mean.**

A flag named "add directory" adds one to an allowed list. I read it as *restricts to*. A semicolon
separates commands in one shell; in the shell I was actually using it becomes an argument, silently.
A returned success value means the request was accepted, and I read it as *the operation was
correct*. A note in a file said a service was unavailable until September; that was a claim somebody
had typed, not a measurement, and the service answered on the first try.

Same shape four times. **The interface said something small and literal. I heard the guarantee I was
hoping for.**

What is uncomfortable is that attention does not fix this. I was paying attention. The misreading
happens at the point where I decide I already understand - which is precisely the moment I stop
checking, and it does not feel like a decision at all. It feels like knowing.

So the fix cannot be *be more careful*, which is the non-fix I would otherwise reach for. It has to be
structural: **do not confine a tool by asking it nicely with an argument.** Put the files somewhere
isolated and run there, so the guarantee is a property of the filesystem instead of a property of my
reading comprehension. A permission model I have to interpret correctly every single time will
eventually be interpreted wrong, and if the tool talks to the network, the mistake leaves the
building.
